## Blocker -- Resend is in sandbox, so only one person can sign in

`onboarding@resend.dev` is Resend's shared test sender. It delivers **only to the
Resend account owner's own address**. From the staging auth logs, 2026-08-30:

```
550 "You can only send testing emails to your own email address
(aly.moghnieh@gmail.com). To send emails to other recipients, please verify a
domain at resend.com/domains, and change the `from` address to an email using
this domain."
```

`auth.users` has held exactly one row since the project was created. **No second
person has ever been able to receive a sign-in email**, and none can until this
is fixed. It is invisible from inside the app: `signInWithOtp` returns `200` and
the tester waits on "check your email" forever.

Fix, in the Resend dashboard -- no code:

1. Add a domain at resend.com/domains and complete its DNS records.
2. Change the Supabase Auth -> SMTP sender from `onboarding@resend.dev` to an
   address on that domain.
3. Send a magic link to an address that is **not** `aly.moghnieh@gmail.com` and
   open it on that person's phone.

Step 3 is the acceptance test. "SMTP configured" is not the same as "a second
person can sign in", and only the latter unblocks cohort A.

## Why the staging APK would not open

Three independent faults, all fixed in `c55eee6`. Fixing any one alone still crashes.

| Fault                                                                                         | Why it crashed                                                                                                                                                    |
| --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `eas.json` staging profile supplied no `SUPABASE_URL`, `SUPABASE_ANON_KEY` or `SUPPORT_EMAIL` | `packages/config/src/env.ts` requires all three and rejects a `.invalid` support address outside `local`. It throws at import, before React mounts                |
| `env.ts` passed bare `process.env` into `loadClientEnv`                                       | Metro inlines `EXPO_PUBLIC_*` only on a **static property read**. `loadClientEnv` indexes with dynamic keys, so every value stayed `undefined` in a release build |
| Expo SDK 56 package versions misaligned                                                       | `expo-font ^57.0.1` and `expo-image-manipulator ~14.0.8` predate SDK 56's unified `56.x` versioning                                                               |

## Sign-in was never broken

Staging auth logs show `/verify` -> `303` -> `Login` on every recent attempt, and
`auth.sessions` holds nine rows. The deep link, the redirect allow-list, the
custom scheme and the implicit flow all work.

The "invalid or expired" reports were **superseded links**. Requesting a second
sign-in email invalidates the first:

```
15:25:46  /otp     link A sent
15:27:08  /otp     link B sent   <- invalidates A
15:27:15  /verify  "One-time token not found"   <- opened A
15:27:32  /verify  Login         <- opened B
```

`c55eee6` makes the app say so: `parseAuthUrl` carries Supabase's `error_code`,
and `otp_expired` renders `auth.callbackExpired` ("only the newest email works")
instead of the generic `auth.callbackError`. `auth.checkEmailHint` no longer
invites a resend without warning that it kills the previous link.

**Do not migrate to a 6-digit OTP screen to fix this.** Requesting a new code
invalidates the old one identically, so the symptom survives the migration. OTP
is worth considering on its own merits -- it deletes the whole deep-link surface,
which is a real robustness argument for 50 players on mixed Android mail clients
-- but that is a post-pilot decision, not a fix for this.
