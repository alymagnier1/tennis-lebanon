## Gotchas on this machine — read before running anything

- **Avast HTTPS scanning** re-signs TLS, so Node CLIs fail with `unable to verify the first certificate`. Export the current root and point `NODE_EXTRA_CA_CERTS` at it. In PowerShell:

  ```powershell
  $c = Get-ChildItem Cert:\LocalMachine\Root | Where-Object Subject -like '*Avast*'; "-----BEGIN CERTIFICATE-----`n" + [Convert]::ToBase64String($c.RawData, 'InsertLineBreaks') + "`n-----END CERTIFICATE-----" | Set-Content "$env:TEMP\avast-root.pem" -Encoding ascii
  ```

  Git uses schannel and is fine. Go binaries (the Supabase CLI) use the Windows store and are fine.

- **Publishing an `eas update`** (checklist §4). Export from a folder with **no `.env` files**, because both local `.env` files still hold the **retired legacy JWT**:

  ```bash
  EXPO_NO_DOTENV=1 npx eas-cli env:exec preview "npx expo export --platform android --output-dir dist --clear"
  ```

  `env:exec` injects the EAS `preview` variables without printing them. Check the `.hbc`: staging URL and `sb_publishable_…` present, no `eyJ…`. The one `127.0.0.1` is the dashboard fallback in `packages/config/src/env.ts`, present since M1 and harmless. Then run `eas update --skip-bundler --input-dir dist --channel staging --platform android --environment preview` and delete `dist`. Publish from `staging` only after merging.

- **Inspecting what phones receive.** Request `https://u.expo.dev/7e52c1bd-5a92-42a0-8b08-ace7d6a96542` with `accept: multipart/mixed`, `expo-protocol-version: 1`, `expo-platform: android`, `expo-runtime-version: 0.2.0` and `expo-channel-name: staging`. The manifest's `launchAsset.url` only downloads with the per-asset `authorization` header from the manifest's `extensions.assetRequestHeaders[<asset key>]`. Keep that header out of logs.
- **Runtime version is the app version** (`0.2.0`). Bump `version` in `apps/mobile/app.json` only for native changes, and never before the new build is installed.
- **Migrations:** `npx supabase db push --dry-run` first, then `npx supabase db push`, from the main checkout (linked to `rvdzalxavpcijbiikkjz`). Never edit an applied migration.
- **CI flake:** the smoke test can fail after every migration has applied, with `failed to set up container networking … supabase_inbucket`. That is the runner's Docker. Re-run only the failed job with `gh run rerun <run-id> --failed`.
- **Auto-merge waits only for _required_ checks.** It is safe on `staging` now; it is not safe on any unprotected base.
- **Vercel failing within seconds** usually means platform config, not code. Read `npx vercel inspect <deployment-id> --logs`.
- **pnpm on Windows:** the `pnpm` launcher in an nvm folder runs on that folder's Node, but everything it spawns uses the first `node` on PATH. `pnpm exec node -v` tells you what scripts get.
- **Prettier** has no parser for `.sql` or `.nvmrc` when they are passed by name; the repo-wide `pnpm format:check` skips them. It is non-idempotent on inline code wrapped in Markdown list items, so run it twice.
- **CRLF:** a local tool rewrites working-tree files with CRLF (no content change; `.gitattributes` normalises on commit; `pnpm format` clears it). Python on Windows also writes CRLF in text mode, so open files with `newline=""`.
- **Git Bash** mangles `rev:path` arguments (`git show origin/staging:.nvmrc`) and `/data` paths for `adb`, so set `MSYS_NO_PATHCONV=1`.
- **Web preview of the app:** `expo start --web` works against staging with the publishable key from `eas.json`, and you sign in with a real account. The launch configs used on 09-30 were reverted in the working copy and are gone. To recreate one, run `expo start --web` from `apps/mobile` through `dotenv -v` with the `eas.json` `staging` values. `.claude/launch.json` is tracked, so do not commit machine-specific paths into it.
- **Emulator:** it cannot run ARM-only builds (SoLoader looks for `lib/x86_64`), it cannot register for push (`Device.isDevice`), and its HTTPS can fail behind Avast. `adb` recipes are in [`HANDOVER_2026-09-26.md`](HANDOVER_2026-09-26.md).
- **Never** paste or log keys. Never type passwords into forms on the testers' behalf.
