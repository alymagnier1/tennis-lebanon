### Two security fixes worth understanding

**`095`** — eight `security definer` functions sat at the default grant, which makes them PostgREST endpoints callable by `anon` with RLS bypassed. The serious one was `append_booking_event`: it takes `p_actor_id` as a parameter, inserts unconditionally, and checks nothing about its caller, so any authenticated user holding a booking id could write booking audit rows attributed to anyone including club staff. That audit trail is what an operator reads to resolve a booking dispute.

**`096`** — two functions stayed reachable by `anon` because their migrations wrote `revoke ... from public` and omitted `anon`. **Supabase grants EXECUTE to `anon` by default, so revoking from `public` alone is a silent no-op.** Neither was exploitable — both refuse anonymous callers in the body — but the body check was the only thing closing the door.

`096` was found by `get_advisors` on the hosted project, _after_ a local sweep had passed. The local sweep tested `proacl is null`, which only finds functions at the default grant; these had an explicit ACL that included `anon`. Both the checklist query and the static validator were corrected.

### Three layers now guard this

1. `.claude/skills/supabase-conventions/SKILL.md` — states the rule
2. `scripts/validate-migrations.mjs` — fails a new definer function with no grant, or a revoke that does not name `anon`. Runs in `pnpm verify:pilot` and CI
3. `STAGING_CHECKLIST.md` §2 — runtime sweep using `has_function_privilege('anon', ...)`. Re-run after any migration that adds a definer function; must return no rows

## Traps

- **Never run `seed.sql` against a hosted project.** It carries `@tennis-lebanon.test` accounts and the `Pilot North/Central/South` fixtures. Staging is clean; keep it that way. `pnpm db:reset` is local-only.
- **Do not apply migrations via the Supabase MCP.** `apply_migration` records a timestamp version (`20260829145028`); this repo uses `001`–`096`. Mixing them makes `supabase db push` see every migration as unapplied and try to re-run it. Use the CLI.
- **The CLI needs `supabase login`** — interactive, no TTY in an agent shell. That step belongs to a human.
- **`pnpm format` reaches into `.claude/worktrees/`** unless `.prettierignore` excludes it. It does now.
- **CRLF**: new files written by some editors trip `format:check`. `pnpm format` fixes it.
- Another session was editing `matches.tsx`, `schedule.tsx`, `SlotPicker.tsx`, `MatchHubMoreSection.tsx` and the locale bundles concurrently. Check `git status` before assuming an uncommitted change is yours.
