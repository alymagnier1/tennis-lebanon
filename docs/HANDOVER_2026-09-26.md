## In flight: PRs #31, #33 (stacked) and #34, previewed together

**Pinned bottom controls touched the navigation bar** (founder's phone, 3-button navigation, 2026-09-27): the invite page's buttons, the tab bar and the match hub's action bar sat exactly on the bar's top edge. Measured from the screenshots, the bar is ~48dp and every control ends on it with 0 px to spare. The inset was reported **correctly**; a zero inset would have put these controls ~50 px behind the bar. The cause is `Math.max(insets.bottom, N)`: once the bar is taller than `N` it adds no gap at all.

A first attempt the same morning (`3c2d321`) assumed the inset read `0`. It floored a zero inset to 48dp, which changed nothing on the founder's phone and added dead space on phones with no bar. It was reverted (`c2bd3cb`). Cursor's local `fix/bottom-safe-area` made the same assumption.

  2. `pinnedBottomPadding(inset, gap)` = `inset + gap` (`lib/stack-screen-padding.ts`). `gap` is each site's old minimum, so a phone with no bar keeps its layout; any bar gets its own height plus the gap. It is applied where `Math.max` was used: the tab bar, the match hub's action bar and dock, the invite footer, the bottom sheet, the generic `Screen`, and the reschedule scroll. Sites already written as `inset + N` (create match, onboarding, club footer) had a gap and are unchanged.

## Gotchas on this machine — read before running anything

- **Avast HTTPS scanning** re-signs TLS. Node CLIs (eas-cli, npx) fail with `unable to verify the first certificate`. `%USERPROFILE%\windows-root-ca.pem` is **stale**. Export the current root from `Cert:\LocalMachine\Root` (subject _Avast Web/Mail Shield Root_) to a PEM and set `NODE_EXTRA_CA_CERTS` to it. Git uses schannel and is fine. Large EAS uploads sometimes reset mid-way — retry once.
- **Publishing an `eas update` safely** (checklist §4, follow exactly): updates do **not** read `eas.json` build-profile env and **do** read local `.env` files. Export with `EXPO_NO_DOTENV=1`, `EXPO_PUBLIC_APP_ENV=staging`, `EXPO_PUBLIC_AUTH_REDIRECT_URL=tennislebanon://auth/callback`, through `eas env:exec preview`, with **`--clear`**. Inspect the `.hbc` (staging URL and `sb_publishable_` present; no `eyJ…` JWT, no `127.0.0.1`), then `eas update --skip-bundler --input-dir dist --channel staging --platform android --environment preview`. Delete `dist` afterwards.
- **Runtime version is the app version** (`0.1.0`). Bump `version` in `apps/mobile/app.json` for a change to native code (a native dependency, the Expo SDK, a plugin that changes native code). The ARM-only ABI plugin does not need one (DECISIONS 2026-09-26). Never bump before the new build is installed — every phone would stop receiving updates.
- **`supabase functions deploy process-notifications --project-ref rvdzalxavpcijbiikkjz --use-api`** deploys without Docker. `supabase db push --linked` applies migrations (dry-run first). Never edit an applied migration — add a new one (latest is 110).
- **Docker Desktop is usually stopped**, so `pnpm db:test` does not run locally; CI's Supabase job runs the full pgTAP suite.
- **A local tool rewrites working-tree files with CRLF.** No content change; `pnpm format` clears it.
- **Git Bash mangles `/data`-style paths** passed to `adb shell` — set `MSYS_NO_PATHCONV=1`. Open a chat on the emulator directly: `adb shell am start -a android.intent.action.VIEW -d "tennislebanon:///match/<id>/chat" com.racketbound.app`. Screenshots: `adb exec-out screencap -p > shot.png`.
- **Prettier is non-idempotent** on inline code wrapped inside Markdown list items; run it twice.
- **Never** paste or log keys. Never type passwords into forms on the testers' behalf.
